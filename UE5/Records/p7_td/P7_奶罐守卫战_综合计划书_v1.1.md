## 3. 定位、目标和边界

**定位**：面向 PC 的固定画面轻量塔防子模式，以“奶罐守护 + 攻击障碍开出额外布防位 + 预设路线切换”验证布局决策是否能承载奶家喜剧风格。

**首要问题**：玩家是否看得懂“先守路”与“让塔暂时打障碍、换未来空间/资源”的风险，是否能主动切换预设路线应对波次，并看懂短时炮塔干扰与恢复时机。

**成功结果**：一局从建塔、守波、切换预设路线、改目标、清障到结算闭环可玩；不同通关/清障目标可以分别达成；路线切换与干扰状态可读且可预测；画面和鼠标定位在两种分辨率可读；工程与源美术可独立交接、回归。

**不在本版承诺**：自由手绘寻路、α 以外的动态占路、颜料/第二货币、12 关、18 塔、3 主题、BOSS/限时击杀模式、隐藏关、联网/排行榜、付费道具、随机肉鸽、可操控英雄、移动炮塔、复杂存档成长、原创配音/音乐。

## 4. 冻结玩法基线

### 4.1 α 竖切范围

| 项 | α 基线 |
|---|---|
| 地图 | 1 张固定单屏地图；20×11 逻辑格；有一个分岔段和两条作者预设、端点相同的路线 A/B；固定正交相机，不平移/旋转/缩放 |
| 建造位 | 8 个可见建造位；2 个由指定可破坏物解锁的隐藏位。每个位置以稳定 CellId 定义，不以贴图像素反推 |
| 奶罐 | 10 点耐久；敌人到达时扣 1（甲种可在测试表内另设伤害，α 正式敌种统一扣 1） |
| 塔 | 3 个原创类别、各 3 级：直线单体输出、范围输出、减速支援。数值/目标规则从数据表读取 |
| 敌人 | 3 个原创类别：普通、快速低血、干扰型；干扰型取代原先“缓慢高血”候选，在固定触发点短暂封锁一座塔的攻击；飞行/分裂/Boss 延后 |
| 波次 | 固定 8 波；第 1 局目标时长 4–6 分钟为试玩目标，不写成硬性模拟常量 |
| 障碍 | 2 个指定目标；攻击不直接扣金币，而是占用选中塔的攻击时间。清除后分别开放一个建造位并给表内固定奖励 |
| 路线控制 | 玩家在波间准备阶段切换路线 A/B；一波开始后锁定路线；两条路线共享起终点，且均预先通过连通性和建造位校验 |
| 目标与结算 | 守完所有波次为通关；10 点完整获得“奶罐完整”章；清完所有指定障碍获得“清障完成”章。两章可分别达成 |
| 输入 | 鼠标左键放塔/选塔/标记目标/选预设路线；右键取消/返回；Space 暂停/继续；Esc 返回。路线按钮只在波间可用；α 暂不做 2× 加速 |
| 随机性 | α 不使用玩法随机；波次、掉落与障碍奖励来自固定 fixture。展示性粒子不进入权威状态 |

障碍目标交互：选中一座塔后点击障碍，该塔切换到指定障碍；障碍被清除或不可达时，该塔恢复默认敌人索敌。目标切换必须在 HUD 明确显示，不能依赖颜色单独提示。玩家可暂停后改布局，暂停状态下模拟不推进。路线仅允许波间切换；切换前检查路径连续、起终点一致，路径格不可建造。

干扰型敌人：越过唯一固定触发点时，对触发点周围最近的一座塔施加 1.5 秒“暂时无法攻击”状态；同一敌人最多触发一次、效果不可叠加，平距时按稳定 CellId 决胜。触发范围、目标塔、状态图标和恢复时间均可观察；不封锁玩家操作，不产生随机目标。

## 5. 工程实现基线

### 5.1 工程结构与接口

| 工程面 | 基线 |
|---|---|
| 运行时代码 | `UE5/NaiwaP0/Source/NaiwaRuntime/P7/`，只新增 P7 命名空间/类；不改 P1–P6 玩法类 |
| 运行时内容 | `/Game/Naiwa/P7/Maps/`、`Data/`、`Art/`、`UI/`；编辑资产由 UE 工程导入，源 PNG/原稿不放 Content |
| 规则状态 | `UNaiwaP7TowerDefenseSubsystem` 或等价的 P7 权威模拟器，持有整数 ID、金币、血量、敌人路径进度、塔/障碍状态；HUD 只读快照，不反写权威状态 |
| 关卡壳 | 独立 P7 GameMode/PlayerController/HUD；第一张地图可从命令行/测试入口打开，不先改主菜单 |
| 数据 | α 先使用 4 份单源数据：Tower、Enemy、Wave、Level/Obstacle；校验 ID、引用、范围和建造格冲突。若 UE DataTable 数组字段/CSV 导入有风险，先做一份隔离重导入样片再定型 |
| 网格映射 | 所有拾取基于 Viewport 的 BoardRect 与连续网格变换；1920×1080、1280×720 各测角点/中心/格线，不使用“除以 96 px”硬编码和全屏像素常量 |
| 模拟 | 固定 1/60 s、无刚体物理；每帧最多推进 4 个追赶步，超出保留为待追赶积压并记录，不静默丢弃模拟事件；视觉插值不改逻辑结果 |
| 路径/索敌 | α 关卡数据为两份同起终点的预设 CellId 路径；波间原子切换，波内不改拓扑；不用 NavMesh。敌人沿路径进度推进。塔按“最靠近终点→稳定 EntityId”选敌；被玩家标记的塔才攻击障碍；干扰敌在固定节点触发固定半径/优先级规则 |
| 确定性 | 固定关卡与操作日志，同一 Development 版本重复运行得到相同权威状态序列/哈希；不宣称跨平台浮点位级确定性或联机锁步 |
| 输入 | 使用项目现有 Enhanced Input 依赖；键鼠映射与屏幕像素/Viewport DPI 分离 |
| HUD | α 用分区的 C++ UMG/现有工程 UI 组件呈现塔栏、金币、波次、奶罐血、选择状态和目标反馈；不得把玩法逻辑堆入单个 >800 行 Widget。Canvas 仅在 A0 样片证明更简单且分辨率通过时采用 |
| 存档/菜单 | α 不改全局菜单和存档。γ 接入现有 `UNaiwaProgressSubsystem` / `UNaiwaMenuSaveGame` 增加 P7 独立记录字段并做旧存档迁移；不另建互不兼容的 SaveGame 槽，不共享 P4/P5 局内状态或货币 |
| 配置/打包 | 地图 cook 路径在 P7 Shipping 验收时才追加 `UE5/NaiwaP0/Config/DefaultGame.ini`；不改 DefaultEngine.ini。正式前先验证主菜单返回、动态加载资源与 Shipping 引用完整 |

### 5.2 固定更新顺序

每个固定模拟步按稳定顺序处理：输入意图 → 路线切换校验（只在波间）→ 建塔/升级/售塔校验 → 波次生成 → 敌人路径推进/固定节点干扰触发 → 塔索敌/冷却 → 投射物/命中 → 伤害/状态 → 死亡与金币 → 障碍受击/清除/开位 → 奶罐伤害 → 胜负判定 → 发布只读快照。优先级先实现并写入 fixture；若同一帧清障与漏怪/干扰触发存在先后关系，必须由规则定义和回归覆盖。

Alpha 实体池和数据量很小，不因预估“200 实体”先做每帧分片复杂化；先 profile，再按 P7 数据加压。禁用 `FMath::Rand()` 等全局随机源参与权威玩法；任何遍历需稳定排序后影响结果。

## 6. 美术方向与制作规范

### 6.1 视觉基线

- 纯 2D 立绘/精灵与固定正交相机；地图可采用轻度斜俯视绘制，但不做透视相机、3D 角色、厚涂景深或屏幕模糊。用 2D 轮廓和遮挡表达层次。
- 扁平、清洁、奶家原创风格；主色使用奶油白、青蓝、橘色/紫色的组合，和背景明度拉开。不得直接套用原作配色、塔造型、角色、字体、图标或版式。
- 塔：稳定底座/塔体轮廓；敌人：明确行进朝向、无塔式底座。去色后仍能分清塔、敌人、障碍、路径、奶罐。类别同时用形状/图标/文字表达，不把红绿或单一颜色作为唯一提示。
- 第一关背景不烘焙路线/可建/锁定状态；路线 A/B、分岔门、可破坏物和状态提示为独立图层。表现和碰撞/CellId 共享关卡数据，不把可玩地图画成不能校准的整幅贴图。
- 奶蛙只在 HUD 使用头像候选，不上场操作、不使用 3D 模型；是否复用已有立绘按 Common 台账验收。未通过时以原创奶罐/状态图标作信息引导，不阻塞 α。

### 6.2 α 美术内容单元基线

计数单位为“独立可见图形/动画帧内容”，不是 PNG 文件数；图集与源稿数量在 A0 后更新 manifest。

| 关卡地面/背景 | 1 张 1920×1080 构图底图，不带路径/障碍状态 | 1080p/720p 裁切可用、明度留白不压 HUD |

## 11. 验收标准

### 11.1 规则/数据验收

- 同一输入日志重复运行，金币、塔、敌人路径进度、障碍、奶罐血、波次和结算哈希一致；纯展示 VFX/SFX 不进入该哈希。
- 建造测试覆盖：空位、路径格、被占格、锁定格、金币刚好、金币差 1；非法输入不扣钱、不生成半成品塔。
- 攻击测试覆盖：选择/取消障碍目标、塔冷却、敌人死亡、同时击杀、障碍最后一击、障碍开位和奖励、目标失效后恢复索敌、奶罐恰好为 0。
- 路线测试覆盖：A/B 两条路线共用起终点、无断段/越界/建造冲突；波间切换后新刷敌人走新路线，已有波内禁止切换；切换输入不会重复扣费或改写已存的敌人路径。
- 干扰测试覆盖：仅固定触发点触发一次；目标塔选择稳定；暂停不流逝干扰计时；效果不可叠加；1.5 秒到期恢复攻击；干扰与敌人漏怪/塔击杀同帧时结果由规则排序决定。
- 清障章与奶罐完整章需分别可达；存在“只通关不清障”和“全清但掉血”可复现 fixture；不得把两个可选目标强制耦合为唯一解。
- 重开不带入局内塔/金币/怪物/障碍，关卡数据没有重复 ID、坐标越界、路线/建造位冲突、奖励负值或未引用数据。

### 11.2 视觉/交互/性能验收

- 至少 5 名目标玩家做形成性试玩；≥4/5 可在 60 秒内理解建塔/波次，≥4/5 能通过提示切换路线并将塔切到障碍目标，≥4/5 能指出干扰何时结束；记录漏怪/错点/误解，不把 5 人样本当统计显著性。
- 美术识别盲测：5 人各看混排缩略图 1 秒，≥4/5 正确区分塔/敌/障碍/路线；灰度截图仍分层；色盲模拟下每类还有图形/符号提示。
- 分辨率 1920×1080 与 1280×720 各实测：四角、中心、格线边界拾取 CellId 正确；HUD 不遮挡主路、塔栏/金罐/目标优先级可读，透明边缘无白边。
- 参考测试机在 Development 场景、100 敌/8 塔压力样例下，Game Thread p95 ≤8 ms，完整帧时间 p95 ≤16.7 ms @1080p；另记录平均值、最大 hitch、硬件型号和 UE 版本。缺硬件记录不得宣称通过。
- Editor/Standalone 开发运行和 Shipping 包各做启动/返回/资源加载检查。α 的 Shipping 门只验证资源和启动，不要求未计划的主菜单入口。

## 13. 风险与砍单原则

| 风险 | 早期信号 | 处理 |
|---|---|---|
| 网格、屏幕和逻辑坐标偏移 | 720p/1080p 点击 CellId 不同 | G1 先做四角/中心校准；使用 BoardRect 变换，冻结后才能造关卡 |
| 同屏可读性不足 | 塔/敌灰度混在一起，路线 A/B、封锁状态和 HUD 遮路 | A0 先做缩略图和灰度评审；状态必须有符号/形状/倒计时，不通过不做满资产 |
| 路线选择缺乏策略或误操作 | 两路线长度/塔位结果完全相同，或玩家在波内误触切路 | A0 用灰盒策略表证明两路至少有一项可感知取舍；路线按钮只在准备阶段可用，确认后显示当前路线 |
| 敌人干扰导致挫败/信息混乱 | 玩家不懂被干扰的塔或效果时长，干扰出现过密 | 干扰固定节点、明确预警、固定 1.5 秒且不可叠加；试玩若不能读懂先降频或移出 α |
| 清障玩法变成点一下自动完成 | 塔攻击障碍不产生漏怪/机会成本 | G1 验证“塔转目标后路上压力上升”可读；若没有决策就重做目标/波次 fixture |
| 目标选择造成误操作 | 玩家不能辨识哪座塔在打障碍 | HUD 在塔上/面板上显示目标标记与取消动作；提示兼顾文字/图标/声音 |
| 经济滚雪球或只能用产金塔 | 清障/升级收益压过防守，某塔成为必选 | α 不引入产金塔；beta 用模拟 fixture 扫金币曲线再考虑是否增加经济塔 |
| 过度扩大塔/关数量 | 塔表无独特定位，地图靠堆 HP | 保留 3→6→8 扩展；12/18 是新范围变更，不自动开始 |
| 跨项目资产复用过早 | 只因文件存在就计入预算/通用库 | 所有复用先列台账、跑样片；失败时继续用 P7 原创占位 |
| P4/P5/P6 争工程/TA | 计划人天不能获得连续投入 | 不写完成日期；在G0由项目负责人核对当前迭代/人员后排程 |

排期受限时依序延期：第二主题 → gamma 扩至 6 关 → beta 新塔/敌人数量 → β 限时占路验证。**α 不砍**：A/B 预设路线切换、建塔/升级、选择攻击障碍、短时干扰预警、清障开位的机会成本、无伤/清障可分别达成、输入坐标正确、可重开和稳定结算。
