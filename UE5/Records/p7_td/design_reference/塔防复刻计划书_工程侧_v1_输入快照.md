## §1 复刻边界：抄什么、不抄什么

| 维度 | 保卫萝卜 | 我们怎么做 | 理由 |
|---|---|---|---|
| 单屏 + 固定路径 + 波次 | 有 | **照抄** | 归因清晰是休闲塔防命根子 |
| 10 点守护物 | 有 | **照抄**（换成奶罐） | 失败可数、可复核 |
| 塔 3 级 + 可卖 | 有 | **照抄** | 决策有重量 |
| 可破坏障碍 → 开出新塔位 + 掉钱 | 有 | **照抄，且做成核心** | 拆解 §1 结论：它把"空间"变成可购买资源 |
| 金萝卜（无伤）/ 全清障碍 | 有 | **照抄**（改名"满罐" / "拆干净"） | 零成本把一次性关卡变可重玩 |
| 18 种塔 | 有 | **分批 6→12→18** | 拆解 §7 明示：塔数≠深度，18 座要 12 关才撑得住 |
| 普通 / 挑战 / BOSS 三模式 | 有 | β 只做普通，γ 加另两种 | 挑战模式成本几乎为 0（改表） |
| 105 关 + 隐藏关 | 有 | **不抄**：12 关 | 它的量是商业模式，不是设计优点 |
| 可操控英雄 | 无 | **也不做**；奶蛙只在场边 | 保住"注意力 100% 在布局" |
| 局内随机（词条/肉鸽） | 无 | **不做**，保持可复现 | 与项目 P3/P4/P5 铁律一致 |
| 角色名 / 塔名 | 瓶子炮、便便、风扇… | **全部改奶家命名**（§8.1） | 那些是 IP 名，玩法不受保护、名字受保护 |

## §4 仿真内核（照抄 P4/P5 已验证的那套，不重新发明）

| 项 | 规格 |
|---|---|
| 步长 | 固定 **1/60**，累加器 + `MaxCatchUpSteps = 4`（P4 是 8，塔防实体更多所以调小，避免追帧尖峰） |
| 物理 | **零** `SimulatePhysics`；塔/敌/弹全是运动学 |
| 随机 | 5 条独立 `FRandomStream`（出怪抖动 / 掉落 / 暴击 / VFX / 音效变体），禁止共用 |
| 禁止项（grep 门禁） | `TMap` 遍历求值、`GetDeltaSeconds()`、`SimulatePhysics`、`FMath::Rand()` |
| 循环 | 玩家建塔塔（14 座）→ 快照 → HUD；渲染层禁止反写状态 |

### §4.1 12 段固定顺序（同帧内不可调换）

`1 输入采样 → 2 建造/升级/卖出结算 → 3 波次导演出怪 → 4 敌人沿路径推进 → 5 抵达奶罐结算 → 6 塔索敌+冷却 → 7 投射物推进 → 8 命中结算（伤害/状态/死亡） → 9 死亡与金币掉落 → 10 障碍物受击/清障开点 → 11 计时器（CD/光环/波间） → 12 胜负判定 + 快照发布`

> 第 8 段内部固定子顺序：**先 AOE 清场 → 再单体伤害 → 最后死亡结算**。塔防"一炮清一片"的判定顺序错了会出现"同一帧内先死的小怪还吃到爆炸"。

### §4.2 确定性验收

`seed + 玩家操作日志 → 12 关逐关哈希 → 对金标 JSON`。α 必须跑通"同 seed 两次哈希一致"，否则后面平衡调参全是幻觉。

## §5 路径与索敌（塔防的两个真算法）

| 问题 | 方案 | 为什么不用常见的那个 |
|---|---|---|
| 敌人怎么走 | 航点折线 + 沿路径标量 `s`（cm），每 tick `s += 速度×状态系数` | 不用 A*：固定路径下寻路是纯浪费，且引入非确定源 |
| 塔怎么选目标 | 优先级链：**最靠前（s 最大）→ 距离最近 → id 最小** | 不用"随机选"：不可复现；不用"最近"单条：会放弃快漏的那只 |
| 范围怎么判 | 地面椭圆距离 `d = √(dx² + (dz/0.55)²)`；表现画椭圆 | 纵深压缩 0.55 后屏幕圆 ≠ 地面圆，画圆就会"看着打不到却打到了" |
| 飞行怪 | 走直线（起点→终点 lerp），无视路径，塔需 `bCanHitAir` | 不做独立空中路径 |
| 深度怎么排 | 每个精灵 `Y = −Z × 0.01`（正交所看向量上不改变屏幕位置） | 纯 2D 没有深度缓冲，靠这一层薄薄的 Y 偏移做遮挡 |

### §5.1 纯 2D 的四条实现约定

| # | 约定 | 原因 |
|---|---|---|
| 1 | 相机固定正交 `OrthoWidth = 2400 cm`，朝 +Y 看 XZ 平面 | 与 P1 同构；**1 px = 1.25 cm**，屏幕坐标即世界坐标，不用投影矩阵反算 |
| 2 | 精灵全放 `Y = 0`，靠 `Y = −Z × 0.01` 拉出 0.01 的深度差 | 正交下 Y 不改屏幕位置，只改遮挡顺序 |
| 3 | **不做透视缩放**：走到后面的敌人不变小 | 保卫萝卜也不缩放；一缩放，"射程"和"体型"两个概念就开始打架 |
| 4 | **不做相机倾斜**：地面压扁 0.55 画死进底图与 tile | 相机一倾斜精灵就被压扁，描边粗细全乱，且美术要反向补偿 |

## §6 输入（鼠标是新增项，其余照旧）

**纯 2D 不用射线**：正交相机下屏幕坐标与世界 XZ 是**线性关系**，`GetMousePosition` 一次映射（`世界X = (屏幕X/1920 − 0.5) × 2400`）即得格坐标，比 P2 的 `DeprojectMousePositionToWorld` 更简单也更稳。`bShowMouseCursor = true` 照 P2。

| 操作 | 键 | 实现 |
|---|---|---|
| 选塔 | 数字键 1–9（两排，Tab 切页） | Enhanced Input 单个 `IA_TD_Hotkey` |
| 建造 | 鼠标左键点塔位 | `IA_TD_Click` → 屏幕→世界线性映射 → 四舍五入到格 |
| 取消 / 卖塔 | 右键 | `IA_TD_Cancel`（卖塔需长按 0.4s 防误触） |
| 升级 | 选中塔后 `E` | 同上 |
| 全部升级同类型 | `Shift+E`（γ 期） | — |
| 暂停 / 2× 加速 | `Space` / `Tab` | 加速只改累加器步进次数，**不改步长** |
| 返回 | `Esc` | 与 P1–P5 一致 |

**只建 3 个 Enhanced Input 资产**（Click / Cancel / Hotkey），不建 18 个塔的独立 Action。

## §7 HUD（用 `AHUD` Canvas，不用 UMG）

**理由**：P4 的 UMG HUD（`NaiwaP4ArtIntegrationWidget.cpp`）已经涨到 **1084 行**，而 P3/P5 的 Canvas HUD 分别 424/243 行且改起来只需重编译。塔防 HUD 每帧都变，Canvas 更合适。

| 区域 | 内容 | 刷新 |
|---|---|---|
| 左上 | 奶罐液面（10 口，每口一个刻度）+ 金币 | 事件驱动 |
| 右上 | 波次 `7/20` + 下一波倒计时 + 2× 状态 | 每 tick |
| 底部 | 塔栏 18 格（6 格一页，Tab 翻页）+ 价格 + 选中态 | 事件驱动 |
| 悬停 | 选中塔时：射程圆（地面贴片，**不是 HUD 圆**）、DPS、升级价、卖出价 | 每帧 |
| 建造位 | 14 个格子的虚影（可建=白、不可建=灰、被遮=带锁） | 事件驱动 |
| 结算 | 满罐 / 拆干净 / 剩余口数 / 用时 / 重开 | 一次 |
