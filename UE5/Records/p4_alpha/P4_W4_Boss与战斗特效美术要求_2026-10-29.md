# P4 W4 Boss 与战斗特效美术要求（2026-10-29）

## 1. 目标与边界

为 P4 Alpha 的 W4 战斗补齐可替换当前占位图的“奶桶队长”Boss 立绘与冲锋/桶盖砸地动作，并提供命中、冲撞和阶段变化的清楚反馈。

- P4 角色采用透明 2D 立绘，固定 2.5D 竞技场机位；动作不改变模拟判定和固定战斗时序。
- 当前 Boss 复用奶盾静态预览立绘。正式 Boss 造型必须与奶盾区分，不能以放大的奶盾图作为最终交付。
- 运行时角色呈现目前按统一 **0.82** 比例缩放。源图继续按统一画布和原始比例交付，不要先把 PNG 内容缩小 18% 再交，否则会发生双重缩放。最终画面比例待负责人开图确认。
- 红色“！”、Boss 攻击文案、血条、伤害数字和场地阴影由游戏运行时绘制，不烘焙进角色或特效帧。
- Boss/VFX 是原 α 美术预算之外的新需求；请在开工前单独报角色、动画、特效工时与所需确认点。

## 2. Boss 角色与动画

### 造型方向

- 角色名/工程 ID：奶桶队长 / 当前 Boss 占位为 `bWaveBoss`。
- 外形应显得比奶丁/奶盾更有压迫感，同时保留 P4 已通过的圆润、软质、Q 萌风格；轮廓、配色和道具应与奶盾明显不同。
- 桶盖是关键视觉道具，动作时要能看清手、桶盖与身体重心；不能遮住脸或把攻击方向藏在身体后面。
- 先交正面、背面、右侧面三向设定和玩家比例对照。侧面可镜像复用；如桶盖/手持物镜像后方向不成立，需明确左右侧是否分别绘制。

### 最小姿势/动作集

1. `idle`：稳定待机，可循环。
2. `move`：追击玩家的短移动循环。
3. `charge_telegraph`：冲锋蓄力，重心和朝向清楚指向锁定的玩家位置。
4. `charge_attack`：沿直线冲出，动作轮廓能与普通移动区分；落点/收势留出脚底锚点。
5. `lid_slam_telegraph`：抬起或举起桶盖，明确表现即将砸地。
6. `lid_slam_impact`：桶盖砸下，地面冲击反馈交由独立 VFX，不画进角色图。
7. `hit`：受击短姿势，保持身体与道具轮廓可读。
8. `phase_two`：半血阶段切换姿势/短循环，可读出 Boss 已强化。
9. `death`：明确的败退/倒地/消散收尾，不与受击姿势混淆。

### 与工程时序对拍

- 冲锋预警 `boss_telegraph_charge`：**0.90 秒**后执行；攻击起点方向锁定玩家位置，正常阶段冲锋距离 280 uu，第二阶段 340 uu。
- 桶盖砸地预警 `boss_telegraph_lid_slam`：**1.05 秒**后执行；正常阶段作用半径 205 uu，第二阶段 248 uu。
- Boss HP 降至 50% 时触发 `boss_phase_two`，阶段切换保护时长 **1.35 秒**。
- 以上时间只用于动作分段和对拍，不要求美术更改游戏速度。最终帧时长由工程对齐模拟事件；不要把 VFX/动画时长写成伤害或碰撞规则。
- 可先用每秒 24 帧制作连续候选；若采用关键姿势/短帧动画，请在 manifest 中提供每帧显示时长。攻击预警阶段不能提前出现命中冲击 VFX。

## 3. 战斗 VFX 需求

请设计一套尺寸克制、可复用的反馈，适配角色缩小后的固定机位。先交一张同屏样片：玩家、敌人、Boss、预警文字和“！”同时存在时，特效不能遮挡危险方向或血量信息。

| VFX ID / 触发事件 | 需要表达的画面 | 说明 |
|---|---|---|
| `fx_melee_impact` / `player_melee_hit` | J 近战命中瞬间的短促接触爆点 | 命中目标处播放；Miss 不显示命中爆点。 |
| `fx_dash_impact` / `player_dash_hit` | 冲撞接触、力量方向和短硬直 | 可由冲撞拖尾加接触爆点组成；不遮挡受击目标。 |
| `fx_enemy_hit` / `enemy_damaged` | 敌人确实扣血时的轻量受击反馈 | 与黄色伤害数字共存时保持简洁；普通受击可共用。 |
| `fx_player_hit` / `player_damaged` | 玩家确实扣血时的红色/暖色冲击反馈 | 与现有受击立绘、红色伤害数字、无敌状态清楚区分。 |
| `fx_boss_charge_trail` / 冲锋动作期间；命中/落空分别由 `boss_charge_hit` / `boss_charge_missed` 结束 | 方向性拖尾或短促尘迹 | 不替代 HUD 预警，不持续覆盖整段战斗画面。 |
| `fx_boss_lid_slam` / `boss_lid_slam_hit` 或 `boss_lid_slam_missed` | 以 Boss 落点为中心的地面冲击圈/波纹 | 两种结果都发生砸地表现；特效本身不代表玩家一定受伤。 |
| `fx_boss_phase_two` / `boss_phase_two` | 1.35 秒阶段转换期间的强化提示 | 可提供普通/强化外观差异；避免闪屏或长时间遮挡。 |
| `fx_enemy_death` / `enemy_killed`；可选 `fx_boss_death` / `boss_killed` | 击败反馈 | 普通敌人可共用；Boss 可单独加强收尾。 |

现有工程事件还包括 `player_melee_miss`、`boss_charge_missed`、`boss_lid_slam_missed`。落空可保留挥空/砸地尘迹，但不得播放“确认命中玩家/敌人”的接触爆点。若美术希望增删触发类别，先与工程确认事件 ID。

## 4. 视觉与技术交付

- 角色帧：透明 PNG，建议统一 512×512 画布；三向脚底锚点稳定，角色每个状态画布和脚底基线一致。提供逐帧源图和可编辑工程文件。
- VFX：优先透明 PNG flipbook/序列，或经 TA 确认后的 Niagara 实现。交付源序列、图集、帧率/每帧时长、锚点/发射点、播放模式、建议持续时间和可变参数；工程负责将其接入 P4 Presenter。
- 建议资产路径：
  - Boss 源稿：`UE5/SourceAssets/P4/Characters/Alpha/W4_Boss/`
  - VFX 源稿：`UE5/SourceAssets/P4/Effects/Alpha/W4/`
  - manifest：`UE5/SourceAssets/P4/Manifests/P4_W4_BossAndVFX_manifest_v01.json`
  - UE 导入件：`UE5/NaiwaP0/Content/Naiwa/P4/Art/Alpha/W4_Boss/` 与 `.../P4/Art/Alpha/W4_FX/`
- 文件名用小写 ASCII，例：`boss_charge_telegraph_side_right_00.png`、`fx_melee_impact_00.png`。manifest 记录事件 ID、方向、帧序、帧尺寸、帧率/时长、循环/一次性、pivot/锚点、透明边距、源文件、版本和 hash。
- 特效使用单独透明图层/贴图；不把场地、HUD、伤害数字、红色感叹号、完整角色截图或固定背景烘焙进序列。
- 命中闪光应短、易读、非全屏；拖尾和冲击圈要给出适用于低动态闪烁的低强度替代帧。避免持续快速高亮闪烁、大面积不透明白屏或遮住 Boss 预警。
- 所有资产只归 P4；不覆盖 P1/P2/P3/P5 源文件，也不将复用素材复制成新的 P4 源资产。

## 5. 分阶段交付与验收

### 第一批：风格确认

1. Boss 三向设定页和玩家比例对照。
2. 冲锋蓄力/出击、桶盖砸地蓄力/命中、半血转阶段的关键姿势页。
3. J 近战命中、冲撞接触、Boss 砸地三种 VFX 单帧/短序列小样。
4. 工时估算和拟采用的序列/flipbook/Niagara 交付方式。

### 第二批：运行时素材

- 批准第一批后再生产完整姿势帧、Boss 状态序列和 VFX atlas。
- 每个动作需明确首帧、命中/冲击帧、末帧和时长；manifest 必须能从文件名恢复状态/朝向/序号。
- 提供透明边缘检查图、逐帧总览、固定机位预览和可编辑源文件。

### 验收条件

- Boss 与奶盾在静止剪影下即可区分；两种 Boss 攻击在预警期间能看出不同的蓄力意图。
- 冲锋方向、桶盖落点和命中特效中心与运行时事件位置一致；不把预警动画误做成实际命中。
- 近战、冲撞、受击、Boss 转阶段效果各自可辨，但不遮挡角色表情、红色“！”、HUD 文字和血条。
- 所有帧三向正确、脚底不跳动、透明边缘无白边/黑框/杂色；图集无串格或裁切。
- 工程导入后由负责人在实际 P4 固定机位开图复核。当前未进行关卡打开或 PIE 视觉验收，不能预先标记通过。
