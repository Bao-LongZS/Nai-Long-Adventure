# P4 工程计划 v2 —— 奶蛙擂台 α / β / γ

日期：2026-10-28 · 状态：**α W2 工程进行中；W1 画面经负责人接受后放行，少量运行/性能证据转后续收口。**  
上位计划：[P4 完整计划 v2](P4_完整计划书_v2.md)；玩法数据：[P4 设计基线 v2.0](design_reference/P4_竞技场设计_v1.md)。

## 1. 工程交付目标

实现 P4 独立竞技场，不接 P1/P2/P3 战斗逻辑或存档槽；由 P4 专用 `APawn`、GameMode、输入映射、模拟状态/Subsystem、数据注册表、Presenter/HUD 和独立 SaveGame 构成。α 交付一个可复现的 5 波/20 敌人/简化 Boss 战斗；β/γ 是否执行由 α 止损/方向门决定。

## 2. 已冻结工程方案

- UE 5.8.3 / `NaiwaRuntime`；新增 C++ 只在 `Source/NaiwaRuntime/P4/**`，内容只在 `/Game/Naiwa/P4/**`。不编辑 P3/P2 文件、共用 Build.cs、默认 GameMode、默认地图或进度存档布局。
- Enhanced Input 使用 P4 自有 `IMC_NaiwaP4`；固定透视机位（57° / FOV 37°，相机距离按标定）；逻辑竞技场 1100×185 uu；1/60 定步长、catch-up 每帧 1–8 步钳制，超出部分保留为模拟积压并暴露待追赶步数，不丢弃模拟步；零刚体 `SimulatePhysics`。
- DataTable + CSV 是数值真源；7 类表按最终 schema 校验。导入错误允许回退手动导入清单，但运行时行值/卡 ID 必须和版本化数据一致。
- 事件按设计冻结顺序进入纯 C++ 模拟；表现层只读。xorshift32 v1、seed、输入日志和完整权威字段状态 hash 构成回放金标；当前已实现的 hash 字段不全，不能提前宣布 A3 通过。
- 2D 角色平面网格 + Unlit alpha 材质，3D 场地只供空间/脚底感；输入朝向、碰撞和行为状态由模拟层决定，表现帧不得反写模拟。

## 6. α 工程硬验收

- A1 可玩性：打包版完成 5 波/20 敌人→Boss→结算，连续三次完整运行，零崩溃/软锁。
- A2 配置精度：W2 冻结参数与模拟实测偏差 ≤10%；须同时有配置表及测量日志，这不替代试玩门。
- A3 确定性：同 seed+输入日志，起点/每波/Boss checkpoint hash 完全一致；哈希覆盖位置、朝向、HP、憋笑/充能、状态、冷却、波次/卡修正、弹体、RNG；PIE 与包对齐。
- A4 笑场：盾顶可被打断；撞墙易伤只延长一次且总窗 ≤2.0 s；Boss 只结束前摇进入恢复，不跳阶段/锁血；触发反馈可读。
- A5 工程结构：按原工程计划行数门禁；sim 不读 DeltaSeconds、不用物理、不以不稳定容器遍历决定结果；DataTable 改值不编译 C++。
- A6 视觉/性能：固定机位与三向脚底/遮挡可读；指定 PC 的 α p95 ≤16.7 ms，连续三次 5 波+Boss 每局无非加载 >100 ms 卡顿。≤8 ms 是完整版预算盘点目标，不作为尚无硬件基线的 W1 替代证据。
- A7 打包/入口：Windows 包、按键、重试、存档隔离正确；菜单模式条须单独批准，未批准时仅为内部地图，不通过“正式入口”分项。
