# P6 工程计划书 —— 第 5 关剧情破案「禁笑令之夜」

版本 v2 · 2026-10-28 · 状态：**M0 证据链纸面校核完成；开工基线已分轨；未进入 UE 实现**  
阶段编号：P6。玩家可见关卡编号：5-1。P5/P6 共用角色、价格、存档、输入口径见[共用接口基线](P5_P6_共用接口基线_v1.md)。

## 一、定位与目标

玩家在奶家村院子调查「静音检测仪判定的人类大笑」。三名嫌疑人都承认昨夜笑过，但没有人触发警报；一只鸭子撞倒廉价感应奖杯，奖杯里的播放芯片才是警报来源。玩家收集证据、用不同皮肤查看同一场景的额外痕迹，再提交三段结案答案。

| 项 | 内容 |
|---|---|
| 玩法形态 | 单人固定 3/4 斜视调查；走近、交互、整理证据、提交结案 |
| 核心支柱 | 误导线索可被证据推翻；皮肤只是不同证据滤镜/能力；错误提交不清线索、不重开长关 |
| 交付范围 | 奶家大院一张固定镜头地图、14 个交互点、12 张证据卡、4 种信息层、线索板、3 段结案与清晨二周目 |
| 前置 | P5 第一次结算后解锁；不要求购买皮肤。新存档首次进 P6 可借用皮肤，不锁核心答案 |
| 当前工程约束 | P3 的 2D 立绘可作为纹理来源，但不能当已验收的 3D 模型；先灰盒验证尺寸/视角，再决定复用。P3 M2 尚未正式场景验收 |

## 二、M0 纸面真相时间线

本时间线是本计划唯一剧本真源，修正原稿中 A 线到场时间与 B 照片相矛盾、检测仪时刻被同时解释为声音起点和采样点的问题。

| 时间 | 事件 | 玩家可取得的证据 |
|---|---|---|
| 23:55 | 奶抖离开门房开始巡夜，沿西侧小路绕行 | G6 巡夜路线记录 |
| 23:57:00 | 奶鸭啄戏台假花，撞到奖杯；奖杯底座撞地，感应播放芯片启动 | G1 产品/结构线索、G5 蹼印与啄痕、S2 撞痕、S3 滑移轨迹 |
| 23:57:01–00:00:01 | 芯片循环播放三分钟“哈哈哈”；静音检测仪将其误判为人类笑声 | G1 芯片说明、G3 仪器采样条、X2 双层重建 |
| 23:57:15 | 奶拍拍下已经倒地的奖杯；照片发亮来自闪光灯 | G4 照片元数据及底片 |
| 23:58:07 | 检测仪打印一条 96 dB、“人类大笑”的分类记录；纸面波形被踩糊，不能单独读出节奏 | G3。23:58:07 是采样/分类时刻，不是循环起点 |
| 00:03 | 奶抖到戏台附近，看见奶鸭滑进垃圾桶后发笑；她没有看到奖杯被撞倒 | G6 时间线 + NPC 口供；S1 视线重建用于交叉验证 |
| 00:12 | 奶拍回看底片，因闪光过曝笑了一声；她的笑不是仪器记录的来源 | G4 元数据 + G6 口供时间 |
| 00:20 | 奶蛙受奶伯委托调查；06:00 是只由错误结案推动的软时限 | 结案提交记录 |
| 03:00 | 调查期间，奶鼻将奖杯扶正并留下一个油手印；手印不是搬运奖杯的证据。他当时开玩笑说“这奖杯闻起来像奶”，自己笑了一声 | G6 时间线；S4 水痕说明事后有人清理过，但不直接证明凶手 |

三名角色关于“我昨晚笑过”的口供都是真的，但分别发生在 00:03、00:12 和 03:00，与仪器警报无关。线索只允许玩家先形成“可能是某人”的假设，不能让文本断言互相不可能的时间事实。

## 三、结案题目与答案

| 段 | 问题 | 正确答案 | 允许提交的其他答案 | 最小可复核证据 |
|---|---|---|---|---|
| 1 | 谁撞倒了奖杯？ | 奶鸭（不是人） | 奶抖 / 奶拍 / 奶鼻 | G5 的蹼印/啄痕与奖杯撞痕相连；S2 或 S3 作为额外交叉验证 |
| 2 | 检测仪录到的“笑声”是什么？ | 奖杯内的感应播放芯片 | 奶抖 / 奶拍 / 奶鼻 | G1 芯片触发说明 + G3 分类记录；X2 可说明重复时长 |
| 3 | 三名嫌疑人谁在说谎？ | 没有人因这次警报说谎 | 奶抖 / 奶拍 / 奶鼻 | G4/G6 的时间线与口供；各人的笑发生在不同时间，奶鼻的手印也在事后 |

**可解性规则：**六张通用证据 G1–G6 必须足以让基准奶蛙解出 3/3；四张皮肤线索用于缩短搜索、增加可信度或制造可回收误判，不作为通关门票。任意单一皮肤 + 通用证据也必须能 3/3。X1/X2 是可选的交叉证据，不进入评级必需项。

## 四、证据目录与数据接口

### 4.1 通用证据（所有角色可取得）

| ID | 证据卡 | 功能与关联问题 |
|---|---|---|
| G1 | 奖杯铭牌与底座结构：低价塑料壳、感应触发、声音播放模块 | 和 G3 合起来说明声音来自设备，而非现场某个人 |
| G2 | 禁笑令与村委会评比公告 | 建立嫌疑人的共同动机；不直接指认凶手 |
| G3 | 检测仪纸条：23:58:07、96 dB、分类为人类大笑；波形/间隔被踩糊 | 给出机器误判结果与采样时刻；不伪装成完整录音 |
| G4 | 奶拍的底片/照片元数据：23:57:15 奖杯已经倒地，亮斑与闪光同步 | 奶拍照片是真实的，排除“她把奖杯照亮或搬倒”的推断 |
| G5 | 奶鸭三趾蹼印、假花啄痕、奖杯底座相同材质擦痕 | 建立鸭子到奖杯的连续接触证据，回答第 1 段 |
| G6 | 巡夜记录、三人各自口供时间、03:00 摊位收摊票据 | 证明 A/B/C 所说的笑和奶鼻接触均不在触发时刻 |

### 4.2 皮肤信息层

| ID | 皮肤 | 显示内容 | 不得显示的内容 |
|---|---|---|---|
| S1 | 奶察 | 依据固定时间戳重建 NPC 位置和视线遮挡；A 在仪器采样时不在戏台前 | 不显示“凶手”标签；无实时 NPC 朝向模拟冒充案发录像 |
| S2 | 奶杀 | 30 cm 低位撞痕、缺口宽度与奖杯/假花接触的破损顺序 | 不把“破损”直接等同某个人的名字 |
| S3 | 奶豪 | 奖杯从戏台边缘滑落的短轨迹、底座撞击点及最终位置 | 不伪造一条“有人抛出奖杯”的抛物线；真相是被撞后滑落 |
| S4 | 奶雨 | 戏台到井边的水流方向、被冲淡的脚印及水痕形成时间 | 不把事后清理直接等同犯罪；该证据允许误导但须可被 G6 推翻 |

每张 S 仅可在对应皮肤/借用状态下采集。皮肤切换次数沿用共用接口基线；借用不改变购买状态。

### 4.3 交叉证据

| ID | 触发组合 | 结果 |
|---|---|---|
| X1 | 在戏台同时查看 S1 与 S2 | “采样时没有人处在能触发奖杯的位置；低位外撞与鸭子的接触痕迹吻合” |
| X2 | 在奖杯同时查看 S3 与 G1 | “奖杯落地触发底座芯片；播放循环约三分钟” |

初版只实现上述两组固定组合，不做任意信息层两两相乘。这样每个组合都可回归，避免组合数量随皮肤数平方增长。

### 4.4 14 个交互点

9 个必看点承载 G1–G6 与 S1–S4；另 5 个点只提供袜子、垃圾桶、屋顶瓦片等笑点，不给唯一答案线索。交互点 ID、所需皮肤、生成证据卡、复用状态、坐标及提示文本写入一份 DataTable/JSON 单源；不得在 Actor 和 Widget 中分别维护文本答案。

## 五、调查流程与反馈

1. 开场 4 s 可演示四种信息层，但必须标注这是“如何查看线索”的教程示例，不提前显示案件答案。
2. 玩家可步行检查；2.5 m 内显示交互提示。鼠标点击或 Space 检查，F 开关当前皮肤的信息层，Tab 在已购/借用角色中切换。
3. 线索板最多 12 张卡，三格结论槽分别对应三段问题。提交前 UI **只标记已收集、时间、来源和可组合卡片**；不得显示答案是否支持某嫌疑人的绿/红正确性反馈。
4. 初次提交 3/3：完美结案，120 票；2/3：结案成立，60 票；≤1/3：奶伯打回、保留线索、错误提交次数 +1，游戏内时钟前进 40 min。
5. 游戏内 06:00 只在错误提交时推进，不按现实墙钟推进。达到 06:00 且仍未结案，结算“案子黄了”；线索保留，重进为清晨版本。
6. 连续三次 ≤1/3 后给“陈词建议”：按玩家已收集证据生成引用清单，但不直接替玩家点正确选项。再次结案仍可获相应首通评级奖励；重玩票只在成功结案时发。
7. 正确结案演出：奖杯倒扣触发芯片、村民集体笑场、检测仪溢出 ERR；此时再揭示奶鸭是肇事者，确保不是在玩家推理前剧透。

目标时长首通 12–16 min，重玩 5–7 min 为待试玩验证的目标，不作为代码常量。5 人试玩的通过率只作为方向信号；至少记录两轮、第二轮在修订线索后执行。

## 六、技术方案（UE 5.8.3）

- `UNaiwaP6InvestigationSubsystem`：唯一权威状态，管理 case phase、已采集证据、试用/皮肤权限、错误提交次数、游戏内时钟、首通评级及奖励幂等。
- `FNaiwaP6ClueRow`：ClueId、点位 ID、InfoLayerId、可见条件、证据文本/图标、关联问题、推理权重、可组合 ID。不得保存或序列化“直接给 UI 的答案红绿灯”。
- `FNaiwaP6CaseDefinition`：NPC 时间线、真实事件、三段题目和答案 ID、错误后果、场景点位、版本号。开发构建可访问 truth 数据；Shipping 的运行时逻辑只比较 ID，不给场景 UI 读取隐藏答案。
- `ANaiwaP6InvestigationGameMode` 与 PlayerController：固定 3/4 视角、无滚动相机、步行与点击/键盘交互、暂停与主菜单返回。
- 世界表现：P3 2D 立绘 billboard + 低多边形/简单 3D 灰盒场景。先做 3 个点位的相机/脚底/遮挡样片；未通过可读性前，不导入 14 点正式场景。
- 信息层实现：视线扇区/遮挡、破损边线、有限轨迹线、水痕材质各一个可关停组件；优先局部 mesh/decal，不引全屏后处理。材质参数、排序、性能必须在 P6 自己的测试图验证，P4 α 结果不替代本关验证。
- 存档：通过共用主存档保存 P6 证据、已结案评级、奶票；失败/重进不丢证据；结案奖励通过唯一 RewardKey 防重复发放。
- 全部答案和证据关系由离线 fixture 校验；Actor/Widget 只读取同一定义，不复制一份线索文案或状态逻辑。

## 八、验收矩阵

### 确定性/数据检查

- 对 5 种玩家配置（基准、奶察、奶杀、奶豪、奶雨）分别枚举 G1–G6 全收集、任意收集顺序、一次/两次切换；题目答案始终为同一固定真相。
- 穷举三题全部选项组合：3/3/2/3/≤1/3 正确数量与结局、奖励、时钟、线索保留一致；RewardKey 不重复。
- 验证 S1/S2/S3/S4 的遮挡、触发位置与所需皮肤；S4 的误导可由 G6 推翻，不允许形成无解分支。
- 验证 06:00 只被错误提交推进；实体交互、暂停、重进、清晨二周目均不重置持久化证据。

### 人玩/视觉检查

- 形成性指标：≥4/5 能在 60 s 内发现 F 会显示一层痕迹；≥4/5 在 20 min 内结案；≥4/5 能描述某个皮肤的具体信息层；记录首猜错误率，不将“必须有 70% 玩家答错”设为通过条件。
- 结案误判目标改为研究问题：是否有人先怀疑 A/B/C、是否能通过新证据自发修正。若正确玩家无法解释证据，视为线索失败；不能为了达到误判率故意抹掉关键证据。
- 视觉验证：1920×1080 与 1280×720 各一轮；角色与证据点可读、4 信息层不互相遮挡、字号/色盲状态可辨；p95 ≤8 ms @1080p。
- 结局笑点由访谈/复述记录，不作“玩家必须笑出声”的单一硬门；音量、字幕速度、跳过功能进入回归。

## 九、范围边界与风险

**本轮不做：**自由镜头、多个院子、随机案件、复杂关系网、语音识别、多人共玩、任意两两线索组合、永久错失证据、购买门槛、敌人战斗。

| 风险 | 处理 |
|---|---|
| 皮肤借用仍无法试完四层 | 提供轮盘两次切换 + 再进可继续；G 证据保持通关充足；若仍困惑改为首次游玩一次免费层切换教程 |
| 线索过直导致无推理 | 线索板不提示支持/反对具体答案；通过多条独立证据确认，不藏唯一解 |
| “人人没说谎”显得像强行翻案 | 口供必须带独立时间；时间点有玩家可检查的数据来源；否则删去“都没说谎”问题 |
| 14 个交互点造成搜寻负担 | 9 个必看点由局部视线提示串接；5 个纯笑点不计时、不挡路线；任意状态 4 min 内能找到主线点 |
| P3 资产与斜视地图不匹配 | M1 先测 billboard/遮挡；不通过则以简单正面立绘作为 P6 独立资产，不硬套旧视角 |
| “复用 P2 mesh/声音”成本被低估 | 逐项做尺寸、视角、授权/路径检查；未导入前不计作已集成 |

## 十、排期前置与决策

1. P3 M2 评审和主存档扩展接口明确后再做跨关卡集成；独立沙盒可先做 M0/M1。
2. 立绘缺口为奶杀中性态、奶雨中性态；P3 的 7 张差分与本两关 2 张新增姿态可并批，但须由统一风格参考审批。人物立绘不阻塞 M0/M1。
3. 第 5 关以“局部 Decal/Mesh”实现四信息层；若样片视觉不清，先减信息层表现复杂度，不改案件逻辑。
4. 本计划保留玩家可见 5-1 的案件结尾与轻喜剧方向；不复用 v3 中相互冲突的时间句、波形数字或“抛物线必然表示有人投掷”前提。
