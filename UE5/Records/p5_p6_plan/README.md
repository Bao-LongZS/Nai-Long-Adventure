# P5 / P6 开工计划包

日期：2026-10-28（Asia/Shanghai）  
状态：**开工基线已整理；P5 M0–M3 源码已通过 UE 5.8 Editor Development 编译，M2 v4 试玩修订已编译、待负责人重新打开地图确认；M3 经济/能力验收待体验；M4 美术尚未接入；P6 尚未进入 UE 实现。P5 地图打开及 Editor 检查由项目负责人接手。**

## 项目归属与目录

P5、P6 是同一个游戏项目 `Nai-Long-Adventure` 中的开发阶段/关卡，不是两个独立项目。源美术统一归本仓库和 UE 工程 `UE5/NaiwaP0` 管理：

| 目录 | 归属 | 用途 | 规则 |
|---|---|---|---|
| `UE5/SourceAssets/Common/` | 全项目 `Nai-Long-Adventure` | 已批准、至少两个关卡会实际引用的美术源资产；玩家/皮肤基础立绘、通用 UI 元素、模板 | 原稿只存一份；关卡在 UE Content 中引用，不复制一份到 P5/P6 |
| `UE5/SourceAssets/P5/` | 本项目 P5（玩家可见 4-1） | 滑雪关专属背景、雪坡、障碍、雪崩和角色动作图集 | 不放在 Common；P5 关卡独占 |
| `UE5/SourceAssets/P6/` | 本项目 P6（玩家可见 5-1） | 奶家大院、三名嫌疑人立绘、证据卡、信息层视觉资源 | 不放在 Common；P6 案件专属 |
| `UE5/SourceAssets/Common/CharacterReferences/` | 本项目角色设定参考 | 用户提供的 `player.png`（奶蛙）与 `Big_Laugh.png`（奶龙母体对照） | 仅供造型校对，不是可直接导入/发布的游戏成品 |
| `UE5/NaiwaP0/Content/Naiwa/Common/` | UE 运行时共用内容 | Common 源文件通过审核后导入一次，资产路径作为唯一引用入口 | 运行时资产由工程/技术美术导入；不得在 P5/P6 再复制 |
| `UE5/NaiwaP0/Content/Naiwa/P5/`、`.../P6/` | UE 运行时关卡内容 | 各关卡导入后的专用 `.uasset` | 只放本关资产；不可将源稿与临时稿混进 Content |

`Common` 不是“可拿来参考”的收集箱。只有确定复用对象、通过对应视觉/导入验收并在两处有真实引用的成品，才从 `P3/P5/P6` 迁入 `Common`；未验收资产仍留在原关卡目录并标 `候选复用`。P3 的 M2 评审未释放前，P3 立绘只能作为候选，P5/P6 用占位图即可先行开工。

## 工程侧与美术侧职责

| 工作 | 主责角色 | 交付/边界 |
|---|---|---|
| 玩法状态、物理/路线/案件数据、存档、解锁、输入、交互、结算、地图触发与碰撞 | Gameplay Engineer | 负责可运行逻辑、日志、数据 fixture 和包内引用；不负责画源稿 |
| 关卡构图、交互点坐标、文案/证据因果、玩法和美术出口门 | Level Designer / Narrative Designer | 提供冻结的点位与内容表；不在 Actor/Widget 里重复维护真相数据 |
| 角色立绘、背景、道具、卡面、特效、UI 视觉源稿 | 2D Artist / Environment Artist | 按各美术计划交付源文件、导出图、变体、帧表和版本说明 |
| 图集、材质源、贴花/遮罩、Unlit/透明边缘、导入 preset 和性能协作 | Technical Artist | 维护视觉资产管线；不承担权威玩法状态和答案逻辑 |
| Editor 样片、视觉集成、碰撞/图像一致、分辨率与性能证据 | Gameplay Engineer + Technical Artist | 双方按接口验收；P5 的 6 个视觉工程人天已含在 25–34 工程人天中 |
| 范围/风格拍板 | 项目负责人（用户） | M1 样片出口门；当前全量 B、2D 奶蛙方向已拍板，不阻塞 M0/灰盒开工 |

## 开工顺序与阻塞关系

| 阶段 | 工程交付 | 美术交付 | 放行标准 |
|---|---|---|---|
| G0 规格冻结（已完成） | P5 规则/路线 fixture；P6 真相时间线、G/S/X 线索矩阵 | P5 全量 B 规格；P6 本计划的 3 点样片规格 | 基线不再以 v3 原稿覆盖；变更走本文末尾的变更规则 |
| G1 并行切片 | P5 纯 C++ 运动 fixture；P6 数据表与 3 个灰盒点位、线索板骨架 | P5 选 1 段雪景 + 1 个奶蛙姿态做 Editor 样片；P6 完成 3 个视角/脚底/遮挡样片 | P5 雪坡/角色/障碍/HUD 可读；P6 三点可达且立绘不遮交互物 |
| G2 批量生产 | P5 100 m 玩法切片；P6 14 个点位交互骨架 | G1 通过后补全 P5 19 PNG/40 帧；P6 批量做场景、证据和信息层视觉 | 任何批量作画前，G1 的样片比例、相机、alpha 和排序先定 |
| G3 集成验收 | P5 完整 1200 m、P6 全调查/结案/存档流程 | 资源导入、图集/贴花核对、UI/场景视觉收口 | 1920×1080 与 1280×720 各通过；性能/引用按工程计划测量 |
| G4 候选包与试玩 | 包内回归及形成性试玩 | 仅修复阻塞可读性/导入问题 | 每条问题有复现步骤、责任人角色和关闭证据 |

P3 M2 释放与主存档接口仅阻塞**生产资产复用和跨关卡接入**，不阻塞 P5/P6 的 M0/M1、占位图灰盒、P5 独立源稿和 P6 3 点局部样片。任何复用必须有尺寸/视角/质量核验记录，不能只凭文件存在就计为完成。

## 人天口径

| 阶段 | 工程 | 美术 | 其他未计入 |
|---|---:|---:|---|
| P5 | 25–34 人天（含 6 天视觉工程/UE 集成） | 10.5 人天 | 新音效制作、超过三轮的美术返工、多路线和扩展动画；现有声音仅在试听后复用 |
| P6 | 28–43 人天（含工程/QA） | 25–34 人天，±35% 初估 | v1 不制作配音/原创音乐；可试听后复用现有音效；P3 资产复用失败导致的大规模重画需在 G1 后重估 |

因此 P5 当前总基线是 **35.5–44.5 人天**；P6 是 **53–77 人天**，不含 v1 未要求的新增录音/配乐。P5/P6 的 M5 可接入经试听和授权确认的现有音效；配音/原创音乐须先走范围变更。两关可平行启动各自 M0/M1；不把“并行”误算成更少总人天。工期换算取决于到岗人数和 P3 释放日期，不在无排班信息时虚构日历完成日。

## 变更规则

玩法规则、资产数量、镜头/色彩基线或工作量发生变化时，提交一条变更记录：改动项、来源、受影响的 P5/P6 工程任务、美术资产 ID、工期影响、回归项、批准人。不能在资产文件夹里用“最终版/最终版2”替代版本记录；清单中的 `AssetId` 和版本号是引用主键。
