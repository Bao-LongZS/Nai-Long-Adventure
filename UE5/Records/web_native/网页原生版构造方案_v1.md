# 网页原生版构造方案 v1.1（开工基线）

日期：2026-10-29（Asia/Shanghai）  
状态：G0 实现进行中。网页壳、P1 开场切片（UE 对应胶囊/移动加速度/刹车/空中控制/跳跃保持、键鼠与触屏 Walk150/Run300 切换）、UE 角色/动画导出和 P2 Rapier 探针已落地；浏览器物理结果、Chaos 对照、基础蛋 GLB 与目标设备验收未完成，G0 尚未过门，G1 未开始。  
目标：同一个固定链接在 PC 和手机浏览器打开；游戏逻辑在玩家设备运行，不使用云端 GPU 串流。

## 0. 评估结论与本版改动

v1 的产品方向正确，但还不适合直接全量移植：

1. **P2 物理时间基准有冲突。** 当前 `NaiwaP2ProjectileDriver` 是手写固定步扫掠，项目 profile 的弹丸步长为 1/120 秒；`p2_ballistics_fixture.json` 声明的是 0.004 秒显式 Euler 轨迹。两者不能不加核对地当成同一条验收基线。
2. **关卡几何的真源没有落到导出任务。** P1 的 v7 JSON 不包含完整地图几何；P2 的结构由 `NaiwaP2SceneLibrary.cpp` 在运行时生成；P3 的 3-2 由确定性 C++ 地图生成器创建。只读现有配置文件不足以重建三者。
3. **资源版本选择容易误用。** `NaiwaCharacter/Naiwa_Character.blend` 是历史版本；项目推荐 E2 位于版本目录。还需要从正式蛋模型交付中冻结每种蛋的具体版本。
4. **G0 以前只有方向，没有可判定的试验。** 没有具体输出物、手机性能门、物理门和失败后的止损条件。
5. **原阶段估算偏乐观。** 没把地图导出、资产基线、物理对照和手机浏览器回归单独纳入计划。

本版已对上述问题作了决策。**可以立即启动 G0；G0 过门后再启动 P1–P3 全量移植。** G0 过门前不承诺 P2 和手机端可达到 UE 逐项同质，也不把 P4/P5 灰盒扩入首版。

当前工作树已有未提交改动。G0 只读取 UE 资产/源码，网页文件只写入仓库根目录的 `WebNative/`；不得通过 reset、checkout、批量格式化或重建来“清理基线”。G0 同时记录 Git HEAD 与关键文件工作树 SHA-256，以便之后复现。

## 2. 固定技术选型

本版不保留并行候选栈，避免每个关卡再次讨论技术方案。

- **单一 Web 应用：** 仓库根目录 `WebNative/`，TypeScript + Vite。用当前可用 Node LTS，并在 G0 创建 `.nvmrc`、精确锁定依赖版本和 `package-lock.json`；禁止浮动版本号。
- **3D/2.5D 显示：** Three.js + WebGL 2；首版不依赖 WebGPU。游戏世界绘制在一个 Canvas，菜单、文字 HUD、触控控件用 HTML/CSS，便于响应式布局和辅助功能。Three.js 当前 `WebGLRenderer` 使用 WebGL 2；官方提供 glTF 加载器用于运行时模型。[WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer) · [GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)
- **P2 结构物理：** Rapier 3D WASM 只负责动态结构体及碰撞响应；弹丸按当前 UE 的手写固定步扫掠/反弹/冲量流程重写为 TypeScript，不把弹丸直接改成 Rapier 刚体。Rapier 有正式 JavaScript/TypeScript WASM 包。[Rapier JavaScript 文档](https://rapier.rs/docs/user_guides/javascript/getting_started_js/)
- **P1/P3 规则：** P1 自定义横版角色碰撞与平台状态；P3 使用格子逻辑和确定性规则。规则模块不直接读写 Three.js 对象。
- **单个应用内分层：** 首版不建多 package workspace，也不引入 React。用普通目录边界隔离规则、输入、渲染和存档；只有确有多应用复用需求后才拆包。
- **存档：** IndexedDB 保存版本化 JSON。沿用本机存档语义，不自动迁移 UE 的二进制 SaveGame；若将来用户提供 UE 导出 JSON，再单独做导入功能。
- **后端：** 单机首版不需要 API、账号或游戏服务器。只需要静态托管/CDN；云存档、排行榜、联机列为独立后续需求。

## 3. 游戏循环、坐标与状态接口

- 渲染使用 `requestAnimationFrame`；各玩法由独立累加器推进固定模拟步。后台恢复时按该模式的明确规则暂停/补步，不让帧率直接改变游戏结果。
- 坐标数据必须带单位：P1/P2 从 UE 厘米或米转换并统一使用 Web 米制；P3 以格为权威单位；像素只用于 HUD/美术呈现。导出 JSON 顶层含 `schemaVersion`、`sourceSha256`、`coordinateSystem`、`unitScale`、`levelId` 和资源引用。
- `InputCommand` 只表达游戏动作，如 `moveX`、`jump`、`toggleGait`、`aimStart/aimMove/aimRelease`、`selectEgg`、`eggAbility`、`placeBomb`、`selectBomb`、`pause`、`restart`。
- 统一关卡接口：`load(levelData)`、`start()`、`step(fixedDelta, commands)`、`pause()`、`resume()`、`restart()`、`dispose()`、`getResult()`。Campaign 不直接读关卡实体。
- P3 按当前 0.1 秒逻辑 tick 起步；P2 结构求解 1/120 秒并按 UE profile 的最大追赶步数处理；P2 弹丸子步、P1 碰撞/平台步在 G0 对齐当前 UE 真值后写进 profile JSON。渲染插值不能改权威模拟时间。

## 5. 各模式施工要求

### P1：横版闯关

- 导入正式 v7 关卡几何和对象 ID，保留 8 个检查点、指定拾取、死亡/复活、移动/限时平台、弹跳板、隐藏尖刺及胜利门槛。
- 状态流保持 `Playing → Dying → Respawning → Playing / Won`。检查点复活必须回安全点并重置对应机关，暂停和重开要与 UE 行为表一致。
- 移动、跳跃、落地、弹跳板和掉落由固定步规则驱动；摄像机跟随局部路段，不把 24,000+ cm 的整关挤在手机单屏里。
- 第一垂直切片只做正式角色 + 正式 P1 地面/首个危险 + 移动/跳跃 + CP01 一次完整死亡复活；全关行为放到 G2。

### P2：物理弹弓

- 由 UE 导出真实 `FSceneLibrary` 几何。每个结构件保留 ID、边界、角色（Foundation/Column/Board/Goal）、支撑关系和可破坏/目标标记。
- 结构件用 Rapier 3D 刚体，侧视运动平面锁定；保留 UE profile 中深度、重力、质量/密度、摩擦、恢复、阻尼、缝隙、去穿透和休眠基线。不能只把块画成 sprite 再判断“打中了几只蛋”。
- 弹丸按 UE `NaiwaP2ProjectileDriver` 的 sweep/反弹/自旋/等量反向冲量契约重写；Rapier 只模拟结构。记录碰撞序列和结构稳定/倒塌判定。
- 保留 2-1、2-2、2-3 的蛋库存和限制、五种能力、飞行中再触发、空发扣蛋、结算与重开。手机和鼠标的拖拽共用同一 `aim*` 命令。
- Chaos 与 Rapier 不追求每个浮点轨迹完全相同。关卡验收使用冻结的参数用例和状态结果：碰撞对象/顺序、目标命中/未命中、结构倒塌类别、剩余弹数、二次能力、阶段切换及胜负。允许的物理容差须在 G0/G3 写入 fixture 后才视为冻结。

### P3：网格迷宫

- 3-1 使用 11×9 固定图；3-2 使用 23×17 确定性地图和显式 seed。先在 C++ generator 导出 seed=正式默认值的快照/hash，再移植随机流、BFS 修路与布局 hash。
- 规则覆盖网格移动、四种炸弹、放弹间隔/容量、引爆/连锁、软砖破坏/掉落、敌人 AI、金蛋、三条命、战争迷雾记忆、出口和五类机关。
- 保留 0.1 s 权威逻辑 tick；火焰、传送、踩板门、尖刺、输送带、断裂地板等状态都从固定 tick 推进。渲染可以平滑插值，不能因 30/60fps 不同而改变时间结果。
- 手机用四向控制/虚拟摇杆和独立放弹按钮；小地图可缩放，炸弹/金蛋/出口标识不能被触控 UI 遮挡。

### P4 / P5 入网条件

P4 需先完成正式敌人、波次、卡牌效果、Boss 反制与玩法/画面验收。P5 需先通过 A1 样片门并冻结正式坡面、障碍、金币、袋鼠点位及动画资产。达标后各写独立数据契约和预算，不在 P1–P3 工期中偷塞灰盒。

## 6. PC 与手机交互

| 模式 | PC | 手机/平板 |
|---|---|---|
| P1 | A/D 或方向键、Space 跳、Shift 切步态、R 重开、P 暂停 | 左侧持续按压的左右区/虚拟摇杆；右侧跳跃键；步态和暂停小按钮 |
| P2 | 鼠标拖拽定方向/力度，松开射击；1–5 选蛋；飞行中点击弹体触发能力 | 单指拖拽/松手射击；底部蛋种栏；飞行中再次点按弹体触发能力；禁止浏览器选中文字和页面回弹 |
| P3 | WASD/方向键、Space/J 放弹、1–4 选弹、Shift 奶鸡跳、R 重开 | 左下四方向键/虚拟摇杆；右下放弹/跳跃；底部弹种栏和暂停入口 |

- 手机优先；横版玩法横屏体验最佳，但不使用网页强制锁方向。竖屏下 P1/P2 显示可见的旋转提示；G0 必须实际比较竖屏/横屏操作，G5 才冻结最终 UX。
- 浏览器页面采用 `100dvh`、safe-area inset、pointer capture、`touch-action: none`（仅游戏区）和窗口 resize 恢复。菜单/按钮保留可访问的 DOM 文本及键盘焦点。
- 音频在玩家第一次点“开始”后初始化。网页切后台时按模式暂停；回来后显示继续提示，不补播长时间游戏模拟。

## 7. G0 开工卡：可行性切片（6–8 工程人日）

G0 是立即可以执行的首个任务，不要求先购买域名或启动公网服务器。负责人需提供可用 Android Chrome 与 iPhone Safari 实机各一台；具体型号/系统版本写进 G0 报告。若暂时没有 iPhone，不能把 iOS Safari 覆盖标成通过。

### 顺序任务与输出物

1. **基线锁定（0.5–1 人日）**：记录 `git rev-parse HEAD`、工作树状态、UE 5.8.3 版本、以下文件和资产 SHA-256：P1 配置/地图、P2 scene/profile/projectile/fixtures、P3 generator/settings/design JSON、E2 Blend/FBX、正式基础蛋 Blend/FBX。输出 `WebNative/docs/baseline-v1.json`。不改 UE 资产。
2. **最小网页壳（1 人日）**：创建单 Vite + TypeScript 应用、版本 lock、加载/错误/unsupported-WebGL2 提示、Canvas resize 和键鼠/触屏统一命令；输出可在本机开发机和同 Wi-Fi 手机打开的页面。
3. **资产探针（1–1.5 人日）**：从冻结的 E2 角色和正式基础蛋导出 GLB；保留骨架/指定动作/材质并写 `asset-manifest.json`。同一模型在 Android、iOS、PC 浏览器检查加载、朝向、尺度、透明边和动画。
4. **P1 垂直切片（1–1.5 人日）**：只读导出正式 v7 地图开场到 CP01 的真实几何；实现移动、跳、一次危险死亡和 CP01 复活；触屏能完成同一路线。
5. **P2 物理探针（1.5–2 人日）**：增加最小只读 C++ 导出入口，直接调用 `FSceneLibrary::Make21`，导出 2-1 塔楼、支撑和弹药数据；移植当前 profile 的动态块参数；实现一发从现有 P2 回归/fixture 选出的已知角度弹丸、扫掠接触和冲量，记录 JSON event trace。至少比较一个命中和一个未命中用例。若现有 fixture 与当前 projectile driver 的步长不同，先从当前驱动生成 G0 fixture 并注明来源，不把 `dt_s=0.004` fixture 偷换为当前真值。
6. **G0 报告（0.5 人日）**：记录设备、浏览器、资源首包大小、首屏时间、5 分钟帧时间 p50/p95、JS/WASM 内存、P2 静置漂移、发射/碰撞事件、已知差异、截图和 Go/No-Go。

### G0 过门条件

全部满足才进入 G1–G5：

- 版本化网页可在 Android Chrome、iPhone Safari、PC Chrome/Edge 本机网络打开，无运行时崩溃或 WebGL context 丢失。
- P1 触屏和键鼠各自能从开场到 CP01，完成移动、跳跃、死亡、复活和继续；坐标与冻结 P1 导出数据对齐。
- 正式 E2 角色及基础蛋 GLB 在三类目标浏览器材质/朝向正确，所需动作可播放；正式资源导出可重复。
- P2 2-1 塔在 5 秒静置时无自发倾倒，基准测点累计漂移 ≤1 cm；弹丸固定步测试能记录预期接触对象，冲量会推动被撞块。完整关卡物理不在 G0 一次性通过条件内。
- 手机游戏 Canvas 以 1280×720 等效内部画布运行 5 分钟，帧时间 p95 ≤33.3 ms，操作无连续丢帧；记录各机型温升/降频现象。若未达门槛，先降场景复杂度和后处理再测。
- baseline、asset manifest、P1 JSON、P2 JSON、G0 报告全部包含源哈希；导出无写回 UE 资产。

未过门时只在 G0 原型修复或调整技术假设；不复制六关、不批量转资产。若 Rapier 不能在目标手机满足结构稳定性/性能门，需先重新评估 P2 简化物理规格或停止网页原生路线，不把未过门的方案计入全量移植。

## 9. 全量验收清单

1. 固定 URL 在正式支持的 Android Chrome、iPhone Safari、PC Chrome/Edge 可打开；无需安装/登录。具体最低系统版本由 G0 设备实测冻结。
2. 主菜单六关解锁、连闯/单关入口、胜利/失败回选关正确；IndexedDB 关闭页面后保留成绩，存档 schema 升级不覆盖旧值。
3. P1：完成正式路线与 CP01–CP08 安全复活；机关状态、必需拾取、暂停、重开和 Won 规则正确。
4. P2：固定关卡数据、弹丸轨迹事件序列、命中/未命中、结构状态、五种能力、弹药、2-3 两阶段和胜负边界通过 parity matrix。物理偏差按 G0 后冻结的数值容差验收，不以“看起来差不多”替代。
5. P3：3-1/3-2 固定 seed 输出同 UE 布局 hash；移动、炸弹、连锁、软砖、掉落、敌人、迷雾、机关、金蛋、出口与生命结算通过。
6. 手机：安全区、触控保持/取消、拖拽捕获、游戏区不滚动、横竖屏提示、音频首触启动、后台恢复和低档设备帧时间通过。
7. PC：键盘焦点、鼠标拖拽、键盘快捷键和窗口缩放通过；鼠标/触控源最终产生同一命令结果。
8. 每关资源按需下载；发布 manifest 使用内容 hash，更新版本后旧缓存可失效；用户运行期间生成的存档不放在静态资源目录。
9. 公网发布前核对二创角色、BGM、效果音和视频素材授权；未许可素材替换后再开放公开链接。

## 10. 发布与运行

- G0/G1 使用本机开发服务器和同 Wi-Fi 实机，不采购域名。
- G5 生成静态站点并绑定固定域名，CDN 只托管网页资源；没有游戏会话服务器、TURN 或云 GPU 账单。
- 若目标玩家主要在中国大陆，在 G5 前核实 ICP 备案主体/资源，确定服务地区和域名方案，实测运营商网络、微信内置浏览器和 4G/5G；不能用开发机局域网结果代替公网可达性。
- Service Worker 可在首版正式链接稳定后再加；每个资源使用 hash 名称、manifest 版本切换，避免网页缓存长期指向旧关卡。

## 11. 立即开工任务

**今天即可启动** Git/UE/资源基线锁定、网页壳和导出器设计，不需要先买域名或云服务器。第 1 周内要把 Android Chrome 与 iPhone Safari 实机型号/系统版本记入设备矩阵；没有设备时先用手头设备做开发，但 G0 的移动端门保持“未验证”，需借到目标设备后才能判定 Go。PC Chrome/Edge 也记录精确版本。

音乐和二创资源公开传播授权是 G5 公网发布前的清单项，不阻塞 G0 或 LAN 原型。公网发布到中国大陆前，另核验域名归属、备案主体和可备案云资源。

工程从 **基线锁定** 开始。先完成 E2/基础蛋资源清单、P1/P2/P3 源文件哈希，再建 `WebNative/` 的最小 Vite 页面；接着做正式角色导出和 P1 开场至 CP01 切片；最后做 P2 2-1 塔楼物理探针。G0 报告给出继续全量移植、先修技术问题或停止路线的明确结论。
